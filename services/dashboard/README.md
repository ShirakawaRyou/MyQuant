# IBKR 模拟交易看板

Windows 10/11 用户可选择[原生本地部署](../../windows/README.md)：官方 TWS/Gateway 登录模拟账户，再用本地启动器运行后台与中文看板。当前已验证的是 Linux 环境中的程序逻辑；Windows 原生执行及你的实际券商联调仍待验证。

独立服务项目，拥有自己的 `pyproject.toml`、`uv.lock` 和进程；研究策略、数据、依赖锁及原冻结记录均保留。中文展示版本只修改研究命令行与报告，使用单独的冻结记录，见 [中文输出说明](../../research/CHINESE_OUTPUT.md)。

看板始终醒目标注“模拟交易 · IBKR PAPER”，需要看板用户名密码。显示账户净资产、现金、持仓、券商盈亏、资产曲线、当日盈亏曲线、买卖成交点、信号、订单、成交及各自原因和时间。数据缺失显示“—”，断线保留最后一次数据并显示更新时间。截图中的测试数据明确标注，不是已连接的账户。

## 已完成与外部前提

- 登录保护、持久会话、登录节流、CSRF 防护与只读数据 API。
- 独立 worker、SQLite WAL 持久账本、唯一信号/订单/成交标识、断线核对及提交不确定状态处理。
- Docker 镜像、Caddy HTTPS、IB Gateway 纸面模式及隔离的持久卷配置。
- 云环境中真实 Chromium 的桌面和手机检查，服务重启与持久化检查。

**尚无真实 IBKR 模拟账户连通、行情权限和模拟成交的验证结果。** 用户尚未提供云服务器与域名、部署 Gateway 或在服务器输入凭据。本项目不会替你购买服务器/域名，当前没有可供外网访问的地址。按 [云端部署和查看说明](../../deploy/DEPLOYMENT.md) 完成这些前提即可继续联调；所有软件装在云服务器上。

## 开发环境

```bash
cd /workspace/MyQuant/services/dashboard
export UV_CACHE_DIR=/workspace/.cache/uv
export UV_PYTHON_DOWNLOADS=never
uv sync --frozen
uv run --frozen pytest -q
```

浏览器测试使用系统 Chromium。当前环境具备 Chromium，实际执行测试；在其他环境缺少 Chromium 时该项会明确跳过，不能声称完成浏览器验证。生产镜像不安装测试工具或浏览器。

当前开发环境的独立服务管理：

```bash
python scripts/cloud_services.py start
python scripts/cloud_services.py status
python scripts/cloud_services.py stop --service web
python scripts/cloud_services.py start --service web
```

这些命令仅用于当前云机器的内部验证，默认只绑定回环地址；不会创建公网入口。账户凭据不通过这些命令传入。`runtime/` 在项目根目录，含私有日志、账本、用户和会话，均被 Git/Docker 构建忽略。进程不会随环境快照保存，需要重新启动。

## 信号、订单与成交

1. **信号**：最近已收盘的美股日线和20/60均线、目标仓位、生成时间、数据口径与原因。没有订单也可能有信号。
2. **订单**：后台保存提交意图后才调用 IBKR。包含目标数量、限价、券商状态、已成量、唯一 `orderRef`、关联信号和操作原因。`Submitted` 不表示已成交。
3. **成交**：只由 IBKR 执行回报建立，按 `execId` 去重；一单可以多次成交。手续费迟到时先显示“待券商回报”，之后补齐。未知父订单的单条成交不会冒充整单已成交。

券商导入的手工订单/成交没有本项目策略原因，会明确标记，不编造理由。页面显示最近300条，完整历史从登录后的 CSV 导出获取。

看板文字、图表悬停提示、订单状态和默认 CSV 导出均为中文。导出保留原始数值、股票代码和记录编号，时间包含时区；目标仓位列采用小数比例，0.2 表示 20%。需要原始英文列名与状态码时，在导出地址添加 `?language=en`。API 和持久账本字段不翻译，便于程序核对。

交易账本由 worker 写入；Web 以 SQLite `mode=ro` 和 `query_only` 读取，生产容器还把交易卷挂载为只读。登录数据库与交易数据库分开，登录和退出不会改变订单。页面没有下单、撤单或启停策略 API。

## 后台执行边界

初始 `PAPER_ORDERS_ENABLED=false`，Gateway `READ_ONLY_API=yes`：只同步账户与记录信号。只有服务器明确启用这两个开关后才会提交纸面限价单。

- 每次连接及实际提交前检查托管账户，任何实盘/未知账户类型都会拒绝；当前只支持 `DU` 编号模拟账户。
- 一个账本绑定一个账户；进程文件锁阻止重复 worker，SQL 条件更新保证订单只能领取提交一次。
- 提交前持久写入 `SUBMITTING`。崩溃/断线后先核对券商挂单、已完成单及执行回报。无法确认则保留 `UNKNOWN` 并暂停后续自动单，不盲目重发。
- 只在美股常规交易时段处理；日线必须覆盖最近完整交易日及整个均线区间。无新鲜实时 bid/ask、只有延迟行情或现金不足时不提交。
- 不自动接管手工持仓。账本成交数量与账户持仓不一致（包括尚未核对的拆股）时暂停该股票，而不是猜测股数或卖掉未知归属的持仓。
- 每轮最多提交一单，有挂单时先等待其状态；不预支未成交卖单的收入。订单为 `DAY`、常规时段限价单，成交时机由券商决定，不保证开盘成交。

策略默认预算来自研究配置的10万美元，单只目标为预算的20%，并受账户美元净值和现金约束；不是把模拟账户的全部资金都投入。IBKR 本阶段信号来自 **IBKR ADJUSTED_LAST** 当时取得的已收盘日线，记录后不回写历史信号。与历史研究的逐日前推总回报数据口径及理想化开盘撮合存在差异，不把它们当作相同业绩。

## 盈亏与持久记录

净资产来自 IBKR 账户摘要，资产变动率包含出入金，不宣称现金流调整后的投资回报。另一个曲线显示 IBKR `reqPnL` 当日盈亏，按券商口径每日重置，展示最近纽约日期的读数；缺失则明确等待回报。它不是累计策略回报。

曲线中的买卖点只来自执行回报；信号用独立标记。数据起点为首次成功连接；IBKR API 对可回取的历史订单/成交有范围限制，不保证自动补齐部署之前或长时间停机期间的全部历史。已获取记录会持续保留，不依赖网页打开。

当前不提供网页交易控制、自动撤单/改单、跨账户组合管理、完整现金流收益率或自动处理所有券商异常。`UNKNOWN` 应先在 IBKR 官方纸面账户界面核对；不要直接改数据库冒充已确认。云机器暂停、网络中断、IBKR重登录或行情权限变化会影响执行，状态会通过更新时间和后台消息显示。
